# Як ми ведемо роботу над лонгрідом

`STYLE-OSINT.md` описує, **яким має вийти текст**. Цей документ — про те, **як
його роблять**: від першого посилання до гілки, готової до вичитки.

Складено після «Африканської кампанії» (91 джерело, ~8 900 слів, три акти).
Кожне правило нижче з'явилося там, де щось пішло не так, і коштувало
переробки.

---

## 1. Окрема гілка на статтю

Гілка створюється **до першого рядка тексту** й називається за slug:

```bash
git switch -c afrykanska-kampaniia
```

- `stagingOnly: true` у фронтматері з першого ж комміту. Знімається аж перед
  публікацією.
- Комміт на кожен завершений акт, а не один наприкінці. Редакція править на
  ходу, і повернутися до вчорашньої версії акту має бути одним `git show`.
- Досьє (`docs/dossiers/<тема>/`) комітиться разом зі статтею **на цій гілці**.
  Сенс саме в цьому: коли джерело зникне з мережі, текст лишиться в
  репозиторії, а sha256 підтвердить, що його не правили. У `master` досьє не
  йде — воно вливається тільки якщо редакція вирішить його там лишити.
- `master` лишається чистим, доки стаття не готова цілком.

## 2. Джерела качаються повністю — до першого рядка тексту

**Найважливіше правило всієї роботи.** Спершу витягується абсолютно весь текст
усіх джерел, і лише потім починається написання. Не «прочитав і запам'ятав», не
«переказав своїми словами» — на диску має лежати повний текст, до якого
зводиться кожна цифра в статті.

Причина технічна: штатне завантаження сторінки віддає **опрацьований** вміст.
Цифри округлюються, підписи під фото зникають, дослівна цитата стає переказом.
Через дві години роботи двадцяте джерело в пам'яті вже не існує — а на диску
лежить.

```bash
export PYTHONIOENCODING=utf-8
python scripts/harvest.py <тема> --urls links.txt
python scripts/harvest.py <тема> --status
```

Що має лежати в теці після прогону:

| Файл | Що це |
|---|---|
| `raw/NN-slug.html` | недоторкані байти + sha256 |
| `text/NN-slug.txt` | основний витяг (trafilatura) |
| `text/NN-slug.full.txt` | **повний дамп сторінки** + перелік рядків, яких немає в основному витягу |
| `manifest.json`, `index.md` | реєстр, генерується скриптом |
| `notes.md` | нотатки з посиланнями на рядки, пишеться руками |

**`.full.txt` — не надмірність.** На «Африканській кампанії» trafilatura
мовчки викидала до 70% сторінки: підписи, врізки, блоки «оновлено», вбудовані
цитати. Саме в них сиділи дати й цифри. Якщо файл уже скачано без повного
дампу — `--refull` добирає його, не перекачуючи.

Окремі випадки:

- **X / Twitter.** Сторінка без JS порожня, а `cdn.syndication.twimg.com`
  ріже довгий допис приблизно на 275 символах. Скрипт ходить в
  `api.fxtwitter.com` і бере допис цілком.
- **Telegram.** `t.me/<канал>/<id>` підмінюється на ембед.
- **Пейвол або `МАЛО ТЕКСТУ`.** Скрипт не пролізе. Тут редакція дістає текст
  руками й кладе його в `text/` **з номера 201** — окремий діапазон, щоб
  ручні файли не зіштовхнулися з нумерацією скрипта, коли той докачає ще
  партію. У шапці файлу — URL, видання, дата, спосіб отримання.
- **Джерело не відкрилося взагалі.** Так і сказати редакції. **Жодного факту
  з джерела, позначеного як непрочитане** — не добудовувати зміст за
  заголовком і URL.

Читати — партіями по 5–8 файлів, після кожної дописувати `notes.md`: факт →
№ джерела → рядок. Розбіжності — окремим блоком, з обома сторонами. `index.md`
скрипт перезаписує при кожному прогоні, тому руками там писати нічого не можна;
`notes.md` він не чіпає ніколи.

Після публікації повні тексти можна прибрати — вони інструмент, а не архів.
Рішення за редакцією.

## 3. План — це список актів, які заповнюються по черзі

Структура узгоджується **до написання** й далі тримається. Стаття пишеться не
цілком, а акт за актом, і кожен показується редакції одразу:

```
лід + рамка → Акт 1 → Акт 2 → Акт 3 → зіставлення → висновок
```

- У кінці написаного лишається маркер того, що далі:
  `{/* TODO: § 09 офіційне проти тіньового → § 10 підсумок */}`. Наступний
  прохід вписує розділ замість маркера.
- Правки редакції прилітають між актами й часто міняють план — це нормально й
  саме заради цього робиться поетапність. На «Африканській кампанії» так
  переїхав лід (з дрона в Греції на свіжий удар по Lady Mariia) і так попередні
  удари поїхали з § 00 у лівійський акт, щоб не повторюватися.
- **Плейсхолдери медіа ставляться одразу**, а не наприкінці, — інакше про
  півстатті ілюстрацій ніхто не згадає. Формат — `data-placeholder` із
  описом того, що саме потрібно, і з умовою публікації. Перед публікацією
  жодного лишитися не має (STYLE-OSINT §5).
- Обсяг на етапі написання беремо **з запасом**: краще зайве, яке редакція
  зріже, ніж недобір, заради якого треба вертатися в джерела.

## 4. Гігієна теми узгоджується на старті

Перед першим рядком редакція формулює правила, специфічні для цього матеріалу.
Вони записуються й перевіряються на кожному акті. З «Африканської кампанії»:

| Правило | Навіщо |
|---|---|
| туареги CNA/FLA ≠ JNIM/аль-Каїда | не грати на російський фрейм про «підтримку тероризму» |
| атрибуція хеджована, формулювання **окреме на кожен випадок** | єдина формула «не підтверджує і не заперечує» неточна: у Судані було «без коментарів», у Малі — пряме заперечення |
| різні модальності: Metagaz — надводний, Lady Mariia — повітряні | інакше зливаються в «Україна б'є по суднах» без розрізнення |
| катер у Греції — дрейф, а не удар | інцидент, а не атака на країну НАТО |
| не називати розкритих іноземними розслідуваннями військових | безпека людей, яких ми не викривали |

## 5. Покликання

Нумерація росте **за першою появою в тексті**. Коли новий розділ вписують у
середину готового матеріалу, послідовність збивається — це не косметика, бо
читач, який іде по номерах, губиться.

```bash
python scripts/audit-refs.py <slug>          # перевірити
python scripts/audit-refs.py <slug> --fix    # перенумерувати за першою появою
npx prettier --write "src/app/(main)/articles/<slug>/page.tsx"
```

Скрипт заразом рахує слова (для `readingTime`), плейсхолдери й ловить
латиницю всередині кириличних слів — типову одруківку при наборі
(«групa», «Lіvійські»).

Обережно з prettier: він переносить `<a className="ref">` на кілька рядків,
тому будь-яка саморобна заміна по тексту має враховувати перенос. Аудит після
`--fix` обов'язковий — мовчазна заміна «нічого не знайшла» виглядає як успіх.
